How to revoke

The consent screen pointed at portal.openfinance.ae · My Consents — the UAE Open Finance Authority's mock revoke page. In v1 of this sandbox it's a pointer, not a working URL; the journey it implies is the same one Plaid Portal models: every connection I've authorized, what data each one can read, when I gave permission, and a one-click stop sharing that wipes the bearer server-side and 401s every subsequent call.

Until that page is real, the local equivalent is DELETE /mcp with Mcp-Session-Id — the sandbox-mcp server destroys the session and forces re-authentication on the next call.

Try the journey for real

The wizard above is a UI mock. To exercise the actual OAuth handshake — 401 challenge, RFC 9728 + RFC 8414 metadata, PKCE-validated /token exchange, bearer-gated /mcp — start the MCP server with the opt-in simulation flag: 

# Anonymous — the production default per PRD D-13
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787

# Opt-in OAuth simulation
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787 --simulate-oauth
# or:
MCP_SIMULATE_OAUTH=1 npx -y @openfinance-os/sandbox-mcp --transport http

A short design memo for this page lives at CLAUDE_PERSONAL_BANKING.md; the OAuth simulation lives at packages/sandbox-mcp/src/transports/oauth-simulation.mjs.

Status & scope

This page is a simulation, not a roadmap. Nothing here changes the load-bearing invariants of the sandbox: spec-driven field metadata (EXP-01), no real customer data (NG4 / EXP-07), no institution-specific operational detail (NG5 / D-14), deterministic generation (EXP-05), Standards baseline v2.1 only (D-01), and no separate contributor branding (NG6). Real UAE bank names appear only in the SME advisory panel pulled from each persona's multi_lfi_footprint.plausible_lfi_candidates — never bound to a populate-rate profile.
