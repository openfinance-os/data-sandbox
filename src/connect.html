Claude for Open Finance

A toggle install that puts Claude inside the regulated rails UAE TPPs depend on — and a bundle of ready-to-run workflows so you can go from added the connector to answered a customer's first PFM question in under a minute.

15 ready-made skills

Same shape as Claude for Small Business's 15 ready-made workflows ("planning payroll, balancing the books, onboarding new employees"), retargeted to a TPP. Each skill is a prompt + tool sequence over the existing @openfinance-os/sandbox-mcp tools — no new server tools required.

    accounts → balances → transactions → SOs → DDs, watermark preserved.
  2. 2Underwriting scenario
    EXP-18 DBR / affordability against pinned illustrative formulas.
  3. 3Cash-flow forecast
    Extrapolate 90 days from recurring SOs + DDs.
  4. 4Expense categorisation
    MCC-clustered with confidence.
  5. 5Salary detection
    Find the inflow that pays the rent.
  6. 6Subscription audit
    Recurring DDs/SOs > 3 cycles.
  7. 7Beneficiary risk review
    Flag stale or unusual beneficiaries.
  8. 8Coverage gap check
    Cross-reference insurance policy vs. assets.
  9. 9Renewal calendar
    Motor / home / health policies coming due.
  10. 10KYC freshness check
    get_party vs. consent window.
  11. 11Affordability uplift
    DBR delta under a hypothetical loan.
  12. 12Multi-LFI footprint reconciliation
    SME personas with primary + secondary + tertiary roles.
  13. 13Statement narrative

    Diff response vs. field_status; flag surprises.

AI Fluency for Open Finance — the 4D framework

Free, self-paced. Same shape as Anthropic × PayPal's AI Fluency for Small Business, retargeted to TPP devs.

PillarSMB framingOpen Finance framing
Delegation which tasks to hand to AI PFM summarisation, categorisation, alerting — never automated credit decisions without human-in-loop
Description prompt-writing best practices how to prompt over v2.1 envelopes (Data / Links / Meta) without hallucinating fields
Discernment QA mechanisms preserve _watermark; reconcile field claims against field_status; never redact mandatory under Sparse
Diligence governance framework synthetic-only guardrails; pinned _specSha; deterministic (persona, lfi, seed) replay for every customer answer

Try the journey for real

The wizard above is a UI mock. To exercise the actual OAuth handshake — 401 challenge, RFC 9728 + RFC 8414 metadata, PKCE-validated /token exchange, bearer-gated /mcp — start the MCP server with the opt-in simulation flag: 

# Anonymous — the production default per PRD D-13
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787

# Opt-in OAuth simulation
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787 --simulate-oauth
# or:
MCP_SIMULATE_OAUTH=1 npx -y @openfinance-os/sandbox-mcp --transport http

A markdown design memo for this page lives at CLAUDE_FOR_OPEN_FINANCE.md; the OAuth simulation lives at packages/sandbox-mcp/src/transports/oauth-simulation.mjs.

Status & scope

This page is a simulation, not a roadmap. Nothing here changes the load-bearing invariants of the sandbox: spec-driven field metadata (EXP-01), no real customer data (NG4 / EXP-07), no institution-specific operational detail (NG5 / D-14), deterministic generation (EXP-05), Standards baseline v2.1 only (D-01), and no separate contributor branding (NG6). Real UAE bank names appear only in the SME advisory panel pulled from each persona's multi_lfi_footprint.plausible_lfi_candidates — never bound to a populate-rate profile.
