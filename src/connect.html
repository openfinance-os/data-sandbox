The journey under the hood. MCP returns 401 WWW-Authenticate: Bearer realm="open-finance-sandbox"; Claude calls authenticate, surfaces the consent URL; the user approves; the browser lands on http://localhost:<port>/callback?code=…&state=…; Claude calls complete_authentication; a bearer token is attached to every subsequent /mcp POST. Try the journey

Two ways to experience the consent flow against this repo's MCP server:

# Anonymous — the production default per PRD D-13
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787

# Opt-in OAuth simulation — surfaces 401 + WWW-Authenticate, /authorize,
# /token, and bearer-validation on every /mcp POST
npx -y @openfinance-os/sandbox-mcp --transport http --port 8787 --simulate-oauth
# or:
MCP_SIMULATE_OAUTH=1 npx -y @openfinance-os/sandbox-mcp --transport http

A markdown design memo for this page lives at CLAUDE_FOR_OPEN_FINANCE.md. The OAuth simulation lives at packages/sandbox-mcp/src/transports/oauth-simulation.mjs.

Status & scope

This page is a simulation, not a roadmap. Nothing here changes the load-bearing invariants of the sandbox: spec-driven field metadata (EXP-01), no real customer data (NG4 / EXP-07), no institution-specific operational detail (NG5 / D-14), deterministic generation (EXP-05), Standards baseline v2.1 only (D-01), and no separate contributor branding (NG6).

The OAuth simulation is opt-in and purely transport-side theatre — it gates the same synthetic payloads behind a bearer token. There is nothing real to protect; the value is letting a TPP demo a customer-facing consent journey end-to-end before they have to wire a real Nebras-Open-Finance client.
