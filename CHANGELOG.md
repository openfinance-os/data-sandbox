### Added — Phase R5 (slice 1): refund / reversal transaction shapes

- **`src/generator/refunds.js`** — new post-pass that walks an account's emitted transactions and selectively emits paired refund / reversal credits. Opt-in per persona via `enable_refunds: true`. Default rate 3% of eligible POS / ECommerce purchases; ~30% emit as full `Reversal` (≤36h after the original) and ~70% as `Refund` (2–14 days later, partial amount 25–100% of original). Both `Refund` and `Reversal` are spec-valid `AESubTransactionType` enum values (spec line 4655). No new envelope shapes, no new enum values.
- **Deterministic side-channel.** Each refund decision uses a PRNG keyed on the original `TransactionId` + a fixed salt, so toggling `enable_refunds` on a persona only ADDS credits — every other transaction stays byte-identical. Same mechanism as Phase R3 MCC noise; EXP-05 invariant preserved.
- **Refund TransactionId convention.** `${originalTxId}-rfd` (well under the spec's 210-char ceiling on `TransactionId`). Refund inherits the original's `MerchantDetails` verbatim, so a TPP's enrichment engine pairing by merchant + amount + temporal proximity resolves the same merchant identity on both halves. `_refundOf` + `_refundKind` (internal underscore-prefixed; strip on export) carry the pairing for the sidecar.
- **Enrichment sidecar surfaces the pairing.** Every refund record gains `refundOf` (original TransactionId) and `refundKind` (`Refund` | `Reversal`). The originating purchase's record keeps both fields null — `refundOf` only ever populates on the credit half. A TPP can score its own pairing heuristic against this ground-truth column or simply read it through.
- **`personas/sme-ecommerce-marketplace.yaml`** opts in — the canonical case (marketplace seller has visible returned-goods refund cycles). Every other curated persona keeps refunds default-off, so existing visual snapshots, underwriting calculations, and analyst-facing fixtures are unaffected.
- **Tests.** New `tests/refunds.test.mjs` (7 cases): opted-in persona emits ≥ 1 refund and ≥ 1 of subtype `Refund`; every refund passes shape (Credit + spec enum + Booked + RFD/REV narrative prefix + merchant match + amount ≤ original + posted-after); non-opted personas emit zero R5 refunds (filters out the existing NSF `Reversal` shape via `TransactionType` discriminator); two builds same `(persona, lfi, seed)` byte-identical refund records; toggling `enable_refunds` only ADDS records (non-refund txs byte-identical across the two runs — the headline side-channel invariant); enrichment sidecar carries `refundOf` + `refundKind` on credit halves, both null on originals; refund `TransactionId` stays within the 210-char spec bound.

### Fixed — Greptile review comments (P1 × 3) on R1.5 / R2

- **`dbaDrift` + `arabicDescriptor` short-circuit asymmetry.** Both helpers had `(variants.length === 0 || rng() >= prob)` — JS short-circuits on `||`, so the prob-gate `rng()` draw was skipped entirely when a merchant didn't declare the corresponding variants array. Result: rng-consumption count per transaction depended on pool structure. Adding `display_variants[]` or `display_variants_ar[]` to a previously-bare merchant in a future pool edit would silently shift every downstream rng draw for any seed that selected it, breaking EXP-05 fingerprint stability across pool revisions. Reordered to `rng() >= prob` first → variants check second so the prob draw fires unconditionally. The variant-pick (rngPick) draw stays conditional on prob hit AND variants existing.
- **`buildDirtyPosNarrative` compounded the same issue via `ar || dbaDrift(...)`** — when `arabicDescriptor` returned a truthy value, the `||` short-circuited and `dbaDrift` was never called. Restructured to call both helpers unconditionally first, then combine with `ar || drifted` over the precomputed values. Both helpers' rng draws now fire on every transaction.
- **`enrichmentFile` overwrite-on-multi-seed.** The manifest write `manifest.personas[personaId].enrichmentFile = relEnrich` sat inside the seed loop. Latent today (no banking persona declares `additional_seeds`), but a future per-seed expansion would silently overwrite all but the last seed's path, and `loadEnrichment({ persona })` resolving against `default_seed` would either read a non-default file or hit the `data.seed !== useSeed` guard. Manifest now carries a seed-keyed map `enrichmentFiles: { '<seed>': '<path>', … }`; loader prefers `enrichmentFiles[useSeed]` with a fallback to the legacy single-string `enrichmentFile` for transitional manifests.

### Added — Phase R2: dirty narratives + synthetic UAE family-conglomerate ownership

- **The raw side now actually looks like UAE wire data.** Six new narrative-grammar helpers in `src/generator/realism.js`, all deterministic on the passed PRNG and probability-gated:
  - **`aggregatorPrefix(rng, channel)`** — payment-rail prefixes. POS deck: `TST*`, `SQ *`, `PYPL*`, `STRP*`, `APL*`, `GPAY*`, `NOON*`, `CRT*`. E-commerce subset narrower. Default prob 0.25.
  - **`terminalSuffix(rng)`** — 4-7 digit terminal / merchant IDs as a separate slash-separated segment so the merchant token stays a clean substring. Default prob 0.5 on POS, 0.8 on ATM.
  - **`emirateCode(rng)`** — population-weighted `DXB|AUH|SHJ|AJM|RAK|UAQ|FUJ`. Replaces the open-coded `'DXB'` constant the legacy POS narrative used.
  - **`dbaDrift(merchant, rng, fallback)`** — swaps the canonical merchant token for a declared `display_variants[]` entry. Lets the same merchant appear as `MARKETMARK HYPERMARKET` and `MMARK HYPRMKT` across transactions — the exact stressor a TPP's name-cleaning step has to recognise as the same entity. The enrichment sidecar always resolves to canonical, so the "Show enriched" toggle is the visible payoff.
  - **`parentGroupPrefix(merchant, registry, rng)`** — UAE-specific. Many international brands here are operated under franchise by large local conglomerates, and the group's commercial entity routinely shows up in the narrative (synthetic analog: `FHG/MARKETMARK DXB`, `ASC/CEDAR PLATE AUH`). Default prob 0.25.
  - **`fxClutter(currency, foreignAmount, rng)`** — appends `<CCY> <amt> <country>` for cross-currency transactions (`USD 3912.00 US`, `GBP 4.20 LDN`). Default prob 0.7 on FX rails.
  - **`arabicDescriptor(merchant, rng)`** — low-probability Arabic-Latin transliteration when the merchant declares `display_variants_ar[]` (e.g. `MAHATTA WAQOOD` for fuel, `SOUQ ZAAFARAN` for Saffron Market). Default prob 0.1.
- **Composer.** `buildDirtyPosNarrative()` stitches the helpers in fixed order — group prefix → aggregator → drifted merchant token → terminal → emirate → optional FX clutter. Keeps the merchant token a substring so the existing cross-link / search substring-match logic (`src/app.js:1791-1811`) continues to function unchanged.
- **`bankishNarrative` cap lifted 22 → 80 chars.** The 22-char cap was generator policy, not a spec limit (v2.1 `TransactionInformation` is `string, 1-500, no pattern`). ### Fixed

- **Persona spend volumes were inert.** Personas declared `groceries_aed_per_month_band` / `fuel_aed_per_month_band` (AED bands) but the generator was reading `*_per_month_count_band` (counts), so every persona except `senior_retiree` defaulted to `[4,9]` groceries / `[2,5]` fuel txs/month. Generator now derives a count from the AED band when no explicit count band is declared, dividing mid-band by the merchant pool's mean typical-tx amount; realised monthly grocery AED now lands inside each persona's declared band.
- **Embed mode was banking-only.** `src/embed.js` hard-coded `dist/SPEC.json` and didn't filter the persona pool by domain; an insurance permalink would have rendered an insurance bundle against the banking spec. Embed now resolves domain through `dist/domains.json` and renders a JSON-inspector preview for non-banking domains.
- **Coverage and field-card lookups missed `Transaction.TransactionReference`** (added to `PROBE_BAND` / `collectProbes` / `FIELD_BANDS`) and the per-endpoint coverage probe missed `Transaction.ValueDateTime` (added to `collectProbesForEndpoint('/transactions')`); the YAML `spec/lfi-bands.banking.yaml` was already correct.
- **`whyEmpty` median copy.** Was "Generator's RNG rolled unfavourably for this row" — but the LFI redactor caches keep/drop per `(path, band)` per bundle, so an absent field is uniformly absent across every row of one `(persona, lfi, seed)`. Reworded to "The simulated LFI didn't populate this field for this bundle (re-roll seed to resample)".
- **`@openfinance-os/sandbox-fixtures` did not ship `lib/ui/`.** `lib/persona-builder/fixture-handler.js` (Workstream C plug-point 2 — Service Worker) and `lib/persona-builder/export-zip.js` (plug-point 3 — static-zip download) both `import { envelopesFromBundle } from '../ui/export.js'`, but `tools/build-fixture-package.mjs` was only copying `src/generator/`, `src/persona-builder/`, and `src/shared/` into the package's `lib/`. Both Workstream C runtime paths failed to resolve their import inside the published npm package. Build script now also copies `src/ui/`; the package's `index.mjs`, `index.cjs`, and `index.d.ts` re-export `envelopesFromBundle`. The new MCP `build_persona` tool depends on the same export.
- **`@openfinance-os/sandbox-mcp` HTTP transport pre-production hardening** before D-13 hosting goes live: idle sessions are now evicted by an interval sweeper after `MCP_SESSION_IDLE_TTL_MS` (default 30 min); a `MCP_MAX_SESSIONS` cap (default 1024) evicts the oldest-by-last-activity LRU-style; DNS-rebinding protection is on by default with the bound `host:port` + `localhost`/`127.0.0.1`/`[::1]` allow-listed and a `--allowed-host h:port` CLI flag (repeatable) for production hostnames; SIGTERM / SIGINT trigger a graceful drain of every active MCP session before exit; every HTTP request now writes a structured log line to stderr (`<ISO> METHOD /path STATUS Nms session=<id8>`); `get_transactions` validates `since` / `until` as ISO8601 via zod (previously `Date.parse('garbage') === NaN` silently passed everything); `get_session` echoes the merged recipe for custom sessions so Claude can iterate on it; `--version` / `-V` flag added; the package's `@openfinance-os/sandbox-fixtures` dep was bumped from `*` to `^0.0.1` so a published `mcp-v*` artefact is reproducible.
- **`@openfinance-os/sandbox-mcp` `get_transactions` overran the host MCP client's tool-result size cap on high-volume personas.** A whole-account transaction list for `hnw_multicurrency` (969 txs ≈ 700 KB pretty-printed), `corporate_treasury_listed` (720+ txs ≈ 460 KB), `salaried_emirati_affluent` (742 txs ≈ 440 KB), or the multi-account fan-out for `sme_trading_business` (243 txs ≈ 161 KB) overflowed the per-tool-result cap. The client spilled the response to a temp file and the wedged turn cascaded — every subsequent tool call returned a generic execution error, including read-only ones like `list_personas`. The bundled `monthly-summary` prompt, which instructs `get_transactions` (no accountId — fan out) followed by category bucketing, hit this on first use. Fixed with: (1) a `limit` parameter (default **50**, hard cap **500**) that keeps the most recent N matching transactions per account in ascending `BookingDateTime` order; (2) when truncation occurs, `_filter.truncated=true` plus a `_filter._paginationHint` describing how to walk backwards via `until=<oldest_kept_BookingDateTime>` or a tighter window; (3) a `summary` boolean that fills `_summary` at the envelope root with `count`, `byDirection.{Credit,Debit}.{count,total}`, `byMonth[]`, and top-10 `topCategories[]` by absolute total — a single small response per account regardless of volume. The `monthly-summary` prompt now uses `summary: true` for the bucketing pass and reaches for the unfiltered list only with a tight `since`/`until` or `minAmount` filter when calling out specific large items. v2.1 spec conformance (EXP-10) is preserved — `AEReadTransaction.Data` is declared `additionalProperties: false` with `required: [AccountId, Transaction]`, so the aggregate lives at the envelope root with an underscore prefix (matching the existing `_filter` / `_watermark` / `_specSha` convention) and `Data.Transaction` stays present as an empty array; a strict TPP consumer that strips underscore-prefixed metadata still gets a conformant envelope. Determinism (EXP-05) is preserved — the cap applies after the deterministic generator and never alters the underlying synthetic data.

### Notes

- **Stale-`dist/` CI guard.** New `tools/check-dist-clean.mjs` runs after `npm run build:spec && npm run build:data` in both the local `npm run ci` script and `.github/workflows/ci.yml`, failing fast with a "run npm run build:spec && npm run build:data" message if any tracked `dist/*.json` artifact drifts from its sources. - **`_site/_headers` is silently ignored on GitHub Pages.** `tools/stage-site.mjs` writes a Netlify / Cloudflare Pages `_headers` file declaring `Access-Control-Allow-Origin: *` and `Cache-Control` on `/fixtures/v1/*`. The current `.github/workflows/deploy.yml` deploys to GitHub Pages, which does not honor `_headers` — so those directives only take effect if the site is moved to a host that does (Netlify, Cloudflare Pages, etc.). Cross-origin `fetch()` against `*.json` on the GitHub Pages URL relies on whatever default CORS GitHub serves (currently permissive for static files, but undocumented as a contract). The file is left in place so a host migration is drop-in; an inline comment in `stage-site.mjs` records the limitation.
